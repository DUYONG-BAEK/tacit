1. 개요 · 범위

현재 기준 (2026-11-09)

목표: 작업자가 HMD(RealWear Navigator 520)를 쓰고 제품을 손에 든 채 돌려 보면, AI 서버가 프레임마다 결함을 찾아 HMD 화면과 폰 화면에 바로 표시하고, 제품 하나가 끝날 때마다 합격·불합격을 판정해 기록한다. 작업자는 수동 모드에서 제품마다 판정이 맞았는지 피드백을 넣고, 이 피드백이 학습 라벨이 된다.

역할 분담

기기하는 일하지 않는 일
HMD카메라 영상 송출(MJPEG 4:3 1440×1080, 품질 80, 초당 10장) · 폰이 BLE로 보낸 화면 표시(판정 글자 · 결함 원 · 면 칩 · 제품 결과) · 폰이 3초 동안 아무 쪽지도 보내지 않으면 스스로 "수동 판정" 화면판정 · 기록
모바일HMD 영상을 받는 대로 AI 서버로 중계(WebRTC) · 서버 메시지를 HMD(BLE)와 폰 화면에 표시 · 작업자 피드백을 서버로 전달 · 서버 이력·사진·디스크 조회 · 통신 로그계산·판정 — 서버 값을 그대로 쓴다. PD·QI 임곗값도 서버가 정한다
AI 서버(엣지)PD(제품 탐지) → QI(불량 탐지) 프레임 판정 · 제품 구간 · 결함 확정 · 제품 판정 · 면 진행 · 사진·DB 기록 · 이력·피드백·디스크 API영상 표시 · 학습(모델은 서버 밖에서 학습해 .pt만 가져온다)

작업자 사용 흐름

#작업자시스템
1HMD 전원을 켠다HMD 앱이 뒤에서 떠 BLE 광고 (화면은 홈 그대로)
2폰 핫스팟을 켜고 사내 Wi-Fi에도 연결HMD는 핫스팟, 서버는 사내 Wi-Fi로
3폰 M-01에서 모드(수동·자동) 확인 → 검사 시작폰이 BLE로 HMD를 찾아 붙고(HMD 영상 주소를 HELLO로 받음), HMD 영상과 AI 서버 연결을 연다. HMD 앱이 앞으로 나와 카메라를 켜고, 폰은 M-07 영상 화면으로 넘어간다
4제품을 들고 멈추지 않고 천천히 돌려 본다HMD 가운데 "검사 중" · 결함 프레임이면 ✕ 불합격(빨강)·? 애매(노랑) + 결함 위치 원 · 아래 면 칩 줄(■ 상면 □ 엣지 □ 하면비닐)
5제품을 내려놓는다1초 뒤 서버가 제품을 끝내고 판정 → HMD에 "✓ 합격"·"✕ 불합격 · 결함 종류" 2초, 폰에 결과 카드, 불합격이면 폰 진동 3회
6(수동 모드) 폰에서 맞음·틀림·확인필요서버에 피드백 저장. 누르지 않고 다음 제품으로 가면 "미입력"으로 남는다
7M-01에서 교대 마감HMD에 대기 화면을 보낸 뒤 연결을 끊는다(HMD는 장애로 보지 않음)
8M-05 이력에서 미입력·확인필요를 정리서버 기록을 조회, 프레임 사진 넘겨 보기·결함 확대, 피드백 수정(변경 기록이 남음). M-06에서 서버 디스크

범위 밖 (지금)

  • 인증·HTTPS (같은 사내망 전제, 피드백은 누구나 수정 가능)
  • 사람의 최종 판정 절차(끄덕임·가로젓기·트레이) — 서버 규격에서 없어졌다. 코드는 호출만 끊어 두었다(HMD 수동 판정 화면의 제스처 안내도 표시만)
  • H.265 전송 — 구현했으나 기본값 보류 (4장)
  • 해상도별 검출률 비교, HMD → 폰 → 서버 → HMD 구간별 지연 실측
  • M-01 점검 6항목, M-02~M-04, M-06 지표 — 화면 예시 데이터
