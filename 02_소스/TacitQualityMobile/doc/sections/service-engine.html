서비스 디스패처 — 이벤트를 한 줄로 세워 C3·C4·C5를 잇다

2026-09-20 완료

부품(C3·C4·C5)이 처음으로 한 줄로 연결됐다. 개발가이드 §2 "이벤트를 한 줄로 세운다". BLE 제스처·Edge 판정·트레이 센서·타이머는 서로 다른 스레드에서 초당 수 건씩 들어온다. 락으로 막으면 교착, 안 막으면 경쟁 상태 — 해법은 락이 아니라 줄 세우기다. 모든 입력을 Channel<Event> 하나로 모아 단일 스레드에서 하나씩 꺼내 상태 기계에 넣는다.

설계 판단 — 가이드보다 개선

가이드는 Persist/Enqueue를 ioScope.launch로 던진다. 그러면 outbox 삽입 순서가 뒤섞여 C5의 "순서가 생명이다" 불변식이 깨진다. 그래서 느린 것(ShowScreen의 ACK 대기·StartTimer의 delay)만 별도 스코프로 던지고, 영속화(Persist·Enqueue·NotifyLead)는 상태 루프 안에서 순차로 await하게 했다. outbox 순서 = 이벤트 처리 순서.

또 순수 엔진 / 안드로이드 호스트를 분리했다 — 로직은 android 무의존 InspectionEngine에, 포그라운드·잠금·알림·실물 주입은 InspectionService에. 덕분에 동시성·순서를 노트북에서 검증할 수 있다.

진행 내역

  • service/EffectSinks.kt — 상태 기계 출력이 나가는 바깥 경계(인터페이스). 시험은 가짜로 갈아끼움
  • service/InspectionEngine.kt — 심장. Channel + 단일 스레드 루프 + 이펙트 분배 + 타이머 왕복 (android 무의존)
  • service/InspectionService.kt — LifecycleService 호스트. 포그라운드·WakeLock·WifiLock·알림 문구 갱신, 실물(LocalStore·HmdRenderer·진동) 주입
  • AndroidManifest 에 InspectionService 등록(foregroundServiceType=connectedDevice)
  • 엔진 단위 시험 5건 전부 통과 — 실제 멀티스레드로 검증

C1/C2 대기 지점: InspectionService의 BLE 는 자리표시자(placeholderBle, 로그만). ConnectionManager(C1)·StreamRelay(C2)가 실물 BLE·Wi-Fi Direct·Edge 소켓을 제공하면 교체하고 이 서비스에서 start 한다. AppState 스냅샷 복원(콜드 스타트 시 마지막 상태 이어받기)도 남은 과제. 다음: 가짜 HMD 도구(HMD팀 병렬 개발) 또는 C1 ConnectionManager(실장비 필요).
