HMD 앱 2단계 — BLE로 SHOW 쪽지 수신 → HUD 화면 표시

2026-10-02 완료 · 실장비 검증

1단계(영상 송출)에 이어, 모바일이 BLE로 보내는 SHOW 쪽지를 HMD가 받아 H-01~H-09 화면으로 그리고 ACK를 돌려주는 부분을 만든다. 상대편은 모바일 HmdRenderer·ShowWire(C4, 단위시험 완료)이다.

설계 판단

항목결정근거
BLE 역할HMD = GATT 서버(광고), 모바일 = 클라이언트개발가이드 ble.connect(HMD_MAC)
UUID설계서에 없음 → 우리가 정의, 서비스 1 + 특성 2(DOWN=write, UP=notify)양쪽 앱이 같은 상수 공유
seq마지막 그린 seq보다 작으면 무시, 같으면 ACK만(재전송 멱등)구조설계서 §3
ACK{"type":"ACK","seq":N,"rendered_at":ms} notify§3 메시지 목록 (HMD→M은 type 키)
ttl_ms>0 이면 시간 후 H-01 대기 화면으로 복귀H-02 합격 1.5초 소거
H-09쪽지/PING 3초 무소식 시 HMD가 스스로 표시R16 · V-M04
화면 방식공통 HUD 틀 1개(상단줄·큰 글씨·본문·키 안내·배경색) + 화면별 매핑프로토타입 10화면 구조 동일, 기존 View 방식 유지

DOWN9e7a1001-…모바일→HMD SHOW·PING (write)

H-09 오탐 방지: 모바일 PING(1초)이 아직 없어서, PING을 한 번이라도 받은 뒤에만 "PING 3초 끊김"을 감시한다. BLE 연결 끊김은 바로 3초 감시. 확인 필요: RealWear 520이 BLE 광고(주변기기 모드)를 지원하는지 — 미지원이면 상태줄에 "BLE 광고 미지원".
범위 밖: 모바일 쪽 실제 BleLink 구현(C1)은 다음 단계. 제스처(GESTURE)·HEARTBEAT·OVERLAY는 3단계.
